# DocuMind — Advanced Hybrid RAG & Redis Optimization Engine

DocuMind is a high-performance, production-grade **Document Ingestion and Chat Engine** built with **FastAPI, React (Vite), Google Gemini (AI Studio), and Redis**. It is designed to demonstrate advanced AI engineering principles, specifically addressing core real-world RAG challenges: retrieval accuracy, response latency, API cost reduction, client spam, and semantic intent caching.

## ⚡ Core Technical Implementations & Learnings

### 1. Semantic Vector Cache (Approach 1)
Instead of matching exact question strings (which fails when phrasing changes), DocuMind implements a **Local Semantic Vector Cache** using a secondary ChromaDB collection:
* **The Math**: Embeddings generated by `gemini-embedding-001` are unit-normalized. DocuMind utilizes Chroma's default **squared L2 distance** to compare incoming query vectors against previously cached query vectors:
  $$\text{L2 Distance} = 2 \times (1 - \text{Cosine Similarity})$$
* **The Optimization**: By setting a tuned threshold of `0.35` (corresponding to an **82.5% Cosine Similarity**), query variations (e.g., *"Where did he study BTech?"* vs. *"From which college did Ramandeep do his BTech?"*) successfully trigger a **Cache Hit**.
* **Performance Impact**: Latency drops from **~1500ms** (calling the LLM) to **< 20ms** (ChromaDB cached retrieval), while completely bypassing LLM token costs.
* **Cache Invalidation**: Whenever a new document is ingested, the cache is cleanly wiped to avoid serving stale context.

### 2. Ensemble Hybrid Search (Weighted Fusion RAG)
Retrieval accuracy is maximized by combining two distinct searching patterns:
* **Semantic Search (Vector Space)**: Retrieves context based on conceptual meaning using embeddings and ChromaDB.
* **Vectorless Search (BM25 Lexical Space)**: Uses the `rank_bm25` algorithm for exact keyword matching, catching specific acronyms, filenames, or unique tokens.
* **Fusion**: Merges both retriever ranks using a LangChain `EnsembleRetriever` with equal `[0.5, 0.5]` weights, ensuring high recall and precise keyword accuracy.

### 3. Distributed Redis Rate Limiting & Session Memory
* **Counter Rate Limiting**: Intercepts requests in FastAPI using a custom dependency that increments an IP-tied counter in Redis. If a client exceeds 10 queries per minute, a `429 Too Many Requests` is raised with a 60-second sliding expiration.
* **Isolated Session History**: Employs **Redis Lists** (`RPUSH`/`LRANGE`) to persist conversation history isolated by unique session IDs generated by the client. History lists are automatically cleaned up using a rolling **2-hour TTL** to preserve memory.

## 🛠 Tech Stack

* **Frontend**: React.js, Vite, Vanilla CSS (Premium Glassmorphism Dark Theme), Lucide Icons.
* **Backend**: FastAPI (Python 3.12), Uvicorn, Pydantic v2 (Strict Data Schemas), Pydantic Settings.

## 🚀 Local Installation & Setup

### Prerequisites
* Python 3.12 (Highly recommended. We use `uv` to handle CPython 3.12 to bypass pre-release version locks).
* Node.js & npm.
* Redis Server (Running locally on default port `6379`).

### 1. Backend Setup
1. Navigate to the backend directory:
   ```bash
   cd backend
   ```
2. Set up virtual environment and install dependencies:
   ```bash
   python3.12 -m venv venv
   source venv/bin/activate
   pip install -r requirements.txt
   ```
3. Create a `.env` file inside `/backend` directory:
   ```env
   APP_NAME="DocuMind Backend"
   DEBUG=True
   REDIS_URL="redis://localhost:6379/0"
   GEMINI_API_KEY="your_google_ai_studio_api_key"
   ```
4. Start the backend:
   ```bash
   uvicorn app.main:app --reload
   ```
* Interactive API Documentation (Swagger) is available at: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)

### 2. Frontend Setup
1. Navigate to the frontend directory:
   ```bash
   cd ../frontend
   ```
2. Install dependencies:
   ```bash
   npm install
   ```
3. Start the hot-reloading development server:
   ```bash
   npm run dev
   ```
* Open the local Vite client: [http://localhost:5173/](http://localhost:5173/)

## 🌐 Production Deployment Specifications

* **Frontend**: Hosted on **Vercel** with Vite configurations detecting `import.meta.env.PROD` to swap between local and live production backend URLs.
* **Backend**: Hosted on **Render** utilizing a custom `PYTHON_VERSION=3.12.12` variable to guarantee stable library compilation on their remote container builds.
* **Redis**: Hosted on **Upstash Serverless Redis** with standard SSL/TLS (`rediss://`) connection strings, guaranteeing permanent, zero-sleep session tracking.
